# Матрица состояний

Матрица — проект целевого поведения. Финальные бизнес-правила блокируются D01–D03; числовые значения существующих enum сохраняются.

## Профили

| Объект | Состояния | Ограничение |
| --- | --- | --- |
| Seller | pending_review → approved/rejected; approved → suspended; повторная подача отдельное review | can_trade требует approved, paid_until в будущем и незаблокированного User |
| Courier | pending_review → approved/rejected; approved → suspended | availability отдельно; новые задания только approved + available |
| PickUpPoint | pending_review → active/rejected; active → suspended/closed | Прежние доставки не исчезают при закрытии |

## ReviewRequest

| Переход | Actor | Условие и эффект |
| --- | --- | --- |
| create → pending | Заявитель через сервис | Право подать, version snapshot, нет другого открытого review |
| pending → approved/rejected | Уполномоченный ревьюер | Нет self-review, назначение соблюдено, target актуален; доменный эффект атомарен |
| pending → cancelled | Допустимый заявитель/оператор | Действие ещё не выполнено; новая версия не переписывает прежнюю |

## Покупка и оплата

Purchase: awaiting_payment → payment_review при подаче доказательства; approve → paid; исполнение → processing; все необходимые посылки готовы → ready_for_pick_up; все получены → completed. Отказ одной попытки возвращает к допустимому ожиданию/разбору по политике, а не автоматически уничтожает покупку. Expired допускается лишь при отсутствии принятого платежа и активного разбора. Disputed блокирует начисление до решения.

PaymentClaim: awaiting_transfer → pending_review → approved/rejected; pending/awaiting могут стать expired/cancelled при допустимой отмене. Approved имеет маркер единственного применения к цели. Late payment после освобождения stock не применяется автоматически.

## Order

| Из | В | Actor | Проверка |
| --- | --- | --- | --- |
| awaiting_payment | paid | Подтверждение оплаты | Purchase реально оплачена |
| paid | accepted_by_seller | Свой продавец | Допустимо исполнять прежнее обязательство |
| accepted_by_seller | packing | Свой продавец | Заказ не отменён/не спорный |
| packing | ready_for_courier | Свой продавец | Фактическая готовность и точка забора |
| ready_for_courier | courier_assigned (новое значение в конце enum) | Подходящий курьер | Атомарно свободен и eligible |
| courier_assigned | in_transit | Назначенный курьер | Подтверждён фактический забор по политике D03 |
| in_transit | delivered_by_courier | Назначенный курьер | Заявлена передача в правильный ПВЗ |
| delivered_by_courier | ready_for_pick_up | Владелец нужного ПВЗ | Подтвердил реальный приём |
| ready_for_pick_up | received | Покупатель/совместный протокол выдачи | Подтверждение владельца покупки |

Cancelled/disputed допустимы не из любого состояния. Матрицу отмены оплаченного/выплаченного заказа утвердить D01, не реализовывать универсальным update status. Settlement происходит после received и согласованного окна спора.

## WithdrawalRequest и кошелёк

| Переход | Деньги | Actor |
| --- | --- | --- |
| create → pending_review | reserved += amount, balance без изменений | Владелец Wallet, проверенный получатель |
| pending_review → approved | Резерв сохраняется | Другой уполномоченный ревьюер |
| pending_review/approved → rejected/cancelled | reserved -= amount один раз, только до начала перевода | По правам и политике |
| approved → processing | Резерв сохраняется | Оператор выплаты, первоначально admin |
| processing → completed | balance -= amount, reserved -= amount + entry | Подтверждён фактический перевод |
| processing → needs_reconciliation | Резерв сохраняется | Неизвестный внешний результат |
| needs_reconciliation → completed | Списание один раз | Оператор доказал перевод |
| needs_reconciliation → разрешённый повтор/отмена | Только после доказанного отсутствия перевода | Оператор с аудитом; автоматического retry нет |

## Telegram

Notification: pending → sending (lease) → sent; временная ошибка → pending с next_attempt_at; постоянная → failed/skipped. Истёкшая lease подбирается recovery, что допускает дубль внешнего сообщения после потерянного ответа. TelegramUpdate аналогично durable pending → processing → processed/failed; domain idempotency отдельно.

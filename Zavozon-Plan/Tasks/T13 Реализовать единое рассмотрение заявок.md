# T13 Реализовать единое рассмотрение заявок

## Результат

## Работа

- Reviews::Decide проверяет actor, target category, assignment, self-review, version и pending.
- Использовать фиксированный registry обработчиков, не произвольную динамику по callback.
- Решение, доменный статус, AuditEvent и уведомления фиксируются вместе.
- Обработчики платежей/вывода/привязки подключать после реализации их сервисов; до этого категория закрыта.

## Предлагаемые сервисы

Reviews::Submit; Reviews::Assign; Reviews::Decide; отдельные обработчики по allowlist

## Входные точки

POST /reviews/:id/approve или reject, либо бот callback; все вызывают один сервис

## Готово, когда

- [ ] Параллельные approve/reject дают одно решение.
- [ ] Approved review не означает completed withdrawal.
- [ ] Повторная подача не переписывает прошлое решение.

## Проверка

Проверять наблюдаемое поведение и ограничения БД, а не только наличие методов. Для рискованных операций обязательны rollback, повтор запроса и гонка. Набор сценариев: [[06 Проверка и готовность]].

Карточка описывает будущую работу. Наличие похожих полей в исходниках не означает, что задача выполнена.

# T11 Реализовать политики и назначение полномочий

## Результат

Проверять actor и владельца во всех входных каналах.

## Пользовательские истории

[[US02 Права и управление участниками]], [[US15 Рассмотрение заявок]]

## Модели

[[M01 User]], [[M20 AuditEvent]]

## Зависимости

- [[T02 Подготовить User и ApiSession]]
- [[T08 Создать TelegramNotification TelegramUpdate и AuditEvent]]

## Работа

- Current user из Bearer только для API; Telegram actor из verified update.from.id.
- Policies по объектам, проверки blocked и против саморевью.
- Admin-only grant/revoke reviewer permissions, bootstrap первого admin и аудит.
- Проверка прав внутри критических сервисов, а не только видимости кнопок.

## Предлагаемые сервисы

Authorization policies; Administration::SetReviewerPermissions; Administration::BlockUser

## Входные точки

Admin API и команды бота только после проверки admin

## Готово, когда

- [ ] Другой User не читает/не изменяет чужие записи по ID.
- [ ] Отозванное право сразу запрещает старую callback-кнопку.
- [ ] Admin, user_id и paid_until из обычных params не изменяют права.

## Проверка

Проверять наблюдаемое поведение и ограничения БД, а не только наличие методов. Для рискованных операций обязательны rollback, повтор запроса и гонка. Набор сценариев: [[06 Проверка и готовность]].

Карточка описывает будущую работу. Наличие похожих полей в исходниках не означает, что задача выполнена.

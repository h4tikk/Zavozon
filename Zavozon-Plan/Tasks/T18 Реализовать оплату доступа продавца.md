# T18 Реализовать оплату доступа продавца

## Результат

Сохранить ручное управление сроком без отдельной подписки.

## Пользовательские истории

[[US09 Оплата доступа продавца]]

## Модели

[[M03 Seller]], [[M12 PaymentClaim]], [[M13 ReviewRequest]], [[M20 AuditEvent]]

## Зависимости

- [[T13 Реализовать единое рассмотрение заявок]]
- [[T17 Реализовать подтверждение входящего платежа]]
- [[D01 Утвердить расчёты и финансовые правила]]

## Работа

- Claim purpose seller_access принадлежит своему Seller; подтверждённое поступление нельзя одновременно применить к покупке и доступу продавца.
- Admin фиксирует согласованный paid_until и основание оплаты; reviewer платежа не обязательно вправе назначать срок.
- Повтор того же действия не добавляет второй срок; изменение срока аудируется.
- При истечении срок проверяется при операции, а job только уведомляет.

## Предлагаемые сервисы

Payments::ConfirmSellerAccessPayment; Sellers::SetPaidUntil

## Входные точки

Admin действие назначения срока после подтверждённого платежа

## Готово, когда

- [ ] Нет SellerSubscription и скрытого автоматического продления.
- [ ] Две callback-доставки не продлевают срок дважды.
- [ ] Обычный seller/reviewer без admin не задаёт произвольный paid_until.

## Проверка

Проверять наблюдаемое поведение и ограничения БД, а не только наличие методов. Для рискованных операций обязательны rollback, повтор запроса и гонка. Набор сценариев: [[06 Проверка и готовность]].

Карточка описывает будущую работу. Наличие похожих полей в исходниках не означает, что задача выполнена.

## Работа

- Вход raw initData → Bearer; токен в памяти, 401 ведёт к осмысленному повторному открытию, не бесконечному login loop.
- Экран профилей/статусов, каталог, корзина, покупки, кошелёк/вывод, статус Minecraft.
- Если личный чат с ботом не связан или бот заблокирован, показать ссылку «Запустить бота» и статус недоступности отправки; это не отменяет уже созданную заявку.
- Никакого in-app центра уведомлений в MVP; сообщения через бота.
- Сохранить idempotency keys при повторах checkout/withdrawal; конфликт payload показать пользователю.
- API поля денег целые; выбрать string representation при выходе за safe integer JavaScript.

## Предлагаемые сервисы

Новые backend query objects/serializers по необходимости, не generic CRUD service

## Входные точки

Контракт для будущего frontend; его текущие исходники не аудировались

## Готово, когда

- [ ] Vue не хранит bot token, не меняет права и не назначает владельца записи.
- [ ] Refresh и просроченные initData имеют понятный сценарий.
- [ ] Частично выданная покупка отображается корректно.

## Проверка

Проверять наблюдаемое поведение и ограничения БД, а не только наличие методов. Для рискованных операций обязательны rollback, повтор запроса и гонка. Набор сценариев: [[06 Проверка и готовность]].

Карточка описывает будущую работу. Наличие похожих полей в исходниках не означает, что задача выполнена.

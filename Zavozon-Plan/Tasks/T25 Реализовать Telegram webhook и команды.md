# T25 Реализовать Telegram webhook и команды

## Результат

## Работа

- Secret header проверяется constant-time до persist; размер/type payload ограничен.
- Сохранить update в inbox и ACK после commit; отдельная короткая приоритетная задача обрабатывает callback.
- Actor только из update.from.id; chat.id не является user id в группе.
- Строгие callback forms: review:approve:id, order:take:id и прочие allowlist; никаких произвольных методов.
- /start связывает личный chat; admin commands выдают права после авторизации.
- answerCallbackQuery выполняется быстро; блокировка/ошибка ответа не откатывает уже принятое решение.

## Предлагаемые сервисы

Telegram::AcceptUpdate; Telegram::ProcessUpdate; Telegram::RouteCallback; Telegram::BindPrivateChat; Telegram::HandleAdminCommand

## Входные точки

POST /telegram/webhook без Bearer, с собственной обязательной проверкой секрета

## Готово, когда

- [ ] Поддельный secret отвергается, повтор update_id не повторяет действие.
- [ ] Старая кнопка после смены прав/статуса возвращает безопасный ответ.
- [ ] Повтор доставки после перезапуска восстанавливается из inbox.

## Проверка

Проверять наблюдаемое поведение и ограничения БД, а не только наличие методов. Для рискованных операций обязательны rollback, повтор запроса и гонка. Набор сценариев: [[06 Проверка и готовность]].

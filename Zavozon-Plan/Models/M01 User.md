# M01 User

## Что есть сейчас

Telegram ID валидируется, присутствуют admin, blocked_at, четыре права ревью, связи с профилями. В БД Telegram ID всё ещё nullable; ссылка minecraft_link_requests не имеет целевой модели.

Основание: `app/models/user.rb; db/schema.rb:170–183`. Это статическое чтение исходников/schema, не проверка живой базы.

## Что изменить

- Сохранить один User для Mini App и бота; Telegram username не является идентификатором.
- Добавить право can_review_withdrawals; сохранить одновременное участие продавцом, курьером и владельцем ПВЗ.
- Добавить связи с Wallet, ReviewRequest (поданные, назначенные, рассмотренные), WithdrawalRequest через Wallet, TelegramNotification и AuditEvent.
- Перенести reviewed_* со старых reviewer_id на общую историю ReviewRequest после backfill.
- Добавить telegram_private_chat_id и признаки доступности личной отправки; записывать только из проверенного личного webhook.
- Для привязки ника: minecraft_verified_at и ссылка на подтверждённую заявку или иная прослеживаемая связь; новый ник сбрасывает подтверждение.

## Поля и ограничения базы

- telegram_user_id bigint, UNIQUE уже есть, NOT NULL добавить после разбора NULL.
- can_review_withdrawals boolean NOT NULL DEFAULT false; остальные права уже есть.
- telegram_private_chat_id bigint nullable; bot_blocked_at datetime nullable.
- minecraft_verified_at datetime nullable; уникальность нормализованного подтверждённого ника закрепить после решения D02.

## Инварианты и границы

- Нельзя прислать admin, права, blocked_at, подтверждение ника или chat_id через обычное обновление профиля.
- Пользователя с историей блокируют; каскадное удаление торговли и денег запрещено.
- Проверить отсутствие дубликатов профилей до введения уникальности.

# M19 TelegramUpdate

## Что есть сейчас

Durable inbox для повторных webhook пока отсутствует.

Основание: `Новая модель; отсутствует в app/models и db/schema.rb`. Это статическое чтение исходников/schema, не проверка живой базы.

## Что изменить

- Сохранять проверенное входящее событие до подтверждения приёма webhook.
- Update ID обеспечивает дедупликацию доставки; бизнес-сервисы отдельно защищают повторные действия.
- Минимальный payload хранить с ограничением размера/срока; секреты и заголовки не сохранять.
- Фиксировать lease, попытки и ошибку, чтобы восстанавливать зависшую обработку.

## Поля и ограничения базы

- telegram_update_id bigint UNIQUE NOT NULL; payload jsonb.
- status pending/processing/processed/failed; attempts_count, lease_until, processed_at, next_attempt_at, last_error_code.
- Если позже появится несколько ботов: уникальность по bot identity + update_id.

## Инварианты и границы

- 200 Telegram выдаётся только после надёжного сохранения; сбой до сохранения допускает повтор.
- Непроверенный секрет не создаёт запись inbox.
- Ошибка сети при ответе callback не отменяет уже принятое доменное решение.

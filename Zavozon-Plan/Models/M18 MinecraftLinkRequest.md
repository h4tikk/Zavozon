# M18 MinecraftLinkRequest

## Что есть сейчас

Проверка и подтверждение привязки ещё не смоделированы.

Основание: `Новая модель; User уже ссылается на отсутствующий класс`. Это статическое чтение исходников/schema, не проверка живой базы.

## Что изменить

- Заявка содержит User, ник и результат фонового наблюдения присутствия.
- Presence status pending/checking/online/offline/failed/cancelled отделён от решения о владении.
- Для ручного подтверждения владения первоначально требовать admin; использовать ReviewRequest и проверяемое доказательство; онлайн сам по себе недостаточен.
- Результат применяется только если запрос всё ещё актуален; старая задача не перезаписывает новый ник.

## Поля и ограничения базы

- user_id, nickname и нормализованное значение, presence_status, checked_at, failure_code.
- request_key, superseded_at/cancelled_at, applied_at, evidence для ручной проверки.
- Ограничение одновременных актуальных запросов на User по выбранной политике.

## Инварианты и границы

- Таймаут/невалидный JSON не превращается в offline.
- Подтверждённый ник уникален без учёта регистра согласно D02.
- Никаких плагинов Minecraft/RCON или автоматических переводов без отдельной задачи и авторизации.

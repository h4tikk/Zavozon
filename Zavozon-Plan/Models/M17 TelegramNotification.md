# M17 TelegramNotification

## Что есть сейчас

Уведомлений и очереди отправки нет.

Основание: `Новая модель; отсутствует в app/models и db/schema.rb`. Это статическое чтение исходников/schema, не проверка живой базы.

## Что изменить

- Единственная модель для уведомлений только через бота; отдельный in-app Notification не вводится.
- Получатель — User для личного сообщения либо разрешённая группа ревьюеров; у группы нет фиктивного User.
- Хранить событие, данные шаблона, адрес доставки, статус и попытки.
- Снимок payload содержит только данные, нужные адресату; сам по себе не даёт разрешения кнопке.
- Создавать в той же транзакции, что доменное событие; pending-записи служат durable outbox.

## Поля и ограничения базы

- recipient_id nullable FK users; chat_id nullable до разрешения личного адреса, для группы задан сервером.
- delivery_key UNIQUE, kind, payload jsonb, subject_type/id при необходимости.
- status pending/sending/sent/failed/skipped, attempts_count, next_attempt_at, lease_until, last_error_code.
- telegram_message_id, sent_at; индексы для pending и просроченной lease.

## Инварианты и границы

- Нужен хотя бы User либо серверный групповой chat_id; никакой рассылки на адреса клиента.
- Sent означает принятие Telegram, не прочтение.
- Не гарантировать exactly once внешней доставки: потерянный ответ может дать дубль сообщения.
- Повтор сообщения никогда не повторяет бизнес-операцию.

# M09 Purchase

## Что есть сейчас

Связь has_many payment_claims уже исправлена. Имя enum передаётся без двоеточия. Модель ждёт products_amount, schema ещё содержит product_amount, а миграция rename уже существует после версии schema.

Основание: `app/models/purchase.rb; db/schema.rb:141–153; db/migrate/20261020154127_fix_column_name_in_purchase.rb`. Это статическое чтение исходников/schema, не проверка живой базы.

## Что изменить

- Проверить фактический статус миграции, не создавать повторный rename вслепую.
- Исправить enum с сохранением целочисленных значений и выбрать единое написание canceled/cancelled.
- Разрешить бесплатную доставку, суммы рассчитывать сервером.
- Агрегировать состояние всех Order; частичная выдача не завершает Purchase.
- Добавить ключ идемпотентности оформления и снимок назначения доставки.

## Поля и ограничения базы

- products_amount, delivery_amount, total_amount — целые достаточной разрядности, NOT NULL и подходящие CHECK.
- UNIQUE user_id + checkout_key для повторов оформления.
- payment_expire_at сохранить либо переименовать новой миграцией с обновлением всех потребителей.
- Проверка total_amount = products_amount + delivery_amount.

## Инварианты и границы

- Одна покупка может иметь несколько попыток PaymentClaim, но не несколько выполнений одного входящего платежа.
- Спор/поздний платёж не маскируются автоматическим expired.
- Только собственная покупка доступна покупателю.

# Проверка и готовность

Эта заметка — будущий acceptance plan, **не отчёт о пройденных тестах**. Сейчас выполнено только чтение исходников и Ruby syntax check моделей.

## Обязательные сценарии

| Область | Проверка | Ожидаемый результат |
| --- | --- | --- |
| Auth | Изменить user.id в подписанной строке, stale/future auth_date, дубли query fields | 401, нет User/session |
| Auth | Одновременный первый вход одного Telegram ID | Один User/Wallet, валидные сессии |
| Auth | Logout, expiry, block, permission revoke | Старый токен/кнопка не дают доступ |
| IDOR | Чужой order/product/cart/wallet/evidence по ID | 403/404, нет утечки/изменения |
| Models | Прямой некорректный insert в БД | NOT NULL/UNIQUE/CHECK/FK срабатывают |
| Review | Параллельные approve/reject; self-review; stale snapshot | Одно решение, запреты соблюдены |
| Checkout | Два клиента покупают последний остаток | Одна успешная покупка |
| Checkout | Повтор ключа, новый payload тем же ключом | Тот же результат либо 409 |
| Payment | Два claims одной Purchase подтверждаются одновременно | Одно применение платежа |
| Payment | Один реальный transfer reference подан для разных покупок/доступа | Одно применение поступления, повтор отвергнут |
| Payment/expiry | Подтверждение и expire одновременно | Нет paid с освобождённым складом |
| Courier | Два курьера нажимают Take | Один назначен, второму конфликт |
| Pickup | Получен один из двух Order | Purchase не completed |
| Stock | Повтор cancel/expire | Stock освобождён ровно один раз |
| Settlement | Повтор job, один User в нескольких ролях, смена owner ПВЗ | Точные доли старым получателям, без дублей |
| Withdrawal | Две заявки превышают available | Только допустимый резерв |
| Withdrawal | Repeated reject/cancel/complete | Резерв и списание меняются один раз |
| Withdrawal | Потерян ответ после реального перевода | Needs reconciliation, резерв сохранён, нет авто-retry выплаты |
| Notification | Crash до enqueue/после Telegram accept, 429, blocked bot | Восстановление/контролируемый дубль сообщения, без повтора денег |
| Webhook | Неверный secret, повтор update_id, crash обработки | Нет поддельного действия; inbox восстановлен |
| Minecraft | Timeout/invalid JSON/чужой онлайн ник/устаревший job | Нет ложного offline или подтверждения владения |
| Migrations | Пустая БД и копия с NULL/legacy review | Контролируемый preflight, сохранение истории |

## Сквозной тест MVP

Два продавца с одобренным и оплаченным доступом → покупатель оформляет по товару каждого → ревьюер подтверждает реальное поступление → каждый продавец собирает → два конкурентных курьера пытаются взять один заказ → назначенный доставляет → владелец ПВЗ подтверждает → первая выдача оставляет Purchase незавершённой → вторая завершает → settlement начисляет доли → продавец подаёт вывод → средства резервируются → другой уполномоченный принимает решение → admin подтверждает фактический перевод → повтор callback не меняет остаток.

Отдельно пройти отказ оплаты, expiry, спор, отказ вывода, неизвестный результат перевода и недоступность Telegram.

## Нужные уровни проверки

- Ruby syntax и Zeitwerk/eager load, затем проверки модели/DB в изолированной среде.
- Интеграционные сервисные тесты на PostgreSQL с настоящими параллельными соединениями и транзакциями.
- HTTP/callback integration tests с контролируемыми Telegram/game adapters.
- Staging: отдельный тестовый бот и БД, реальные внешние действия только после отдельного разрешения.
- Fixture данные привести к новым уникальностям; старые шаблонные дубли не выдавать за прикладные тесты.

## Общее определение готовности карточки

Критерии истории выполнены, зависимости закрыты, ограничения базы проверены, негативные/повторные сценарии пройдены, данные мигрированы без потери, контракт API/bot обновлён. Для денег и конкуренции есть rollback/race test. Для сети — timeout/recovery. «Метод написан» или «Ruby -c прошёл» не означает готово.

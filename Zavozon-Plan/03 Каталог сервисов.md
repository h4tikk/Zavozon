# Каталог новых сервисов

**Существующие сервисы не читались.** Имена ниже — новая предлагаемая структура, не утверждение об их наличии. Пакеты использовать Users/Sellers/Couriers, не module User/Seller/Courier поверх одноимённых классов моделей.

## Контракт операции

Вход: actor из проверенного канала, ID цели, минимальные данные действия и idempotency key там, где повтор создаёт деньги/заказы. Выход: доменный результат без HTTP/Telegram response. Ошибки: Unauthenticated, Forbidden, NotFound, InvalidState/Conflict, ValidationFailed, InsufficientFunds, InsufficientStock, ExternalUnavailable. Представление HTTP и callback отделено от бизнес-правила.

Критические сервисы сами проверяют actor, состояние и ограничения; повторный вызов из Job или bot не обходит авторизацию. Системным операциям нужен явный системный контекст, а не скрытый User.admin=true.

## Требования к транзакциям

- Reviews::Decide: target/версия + review + доменный результат + audit + outbox в одной транзакции. Не вызывать Bot API под блокировкой.
- Checkout::PlacePurchase: snapshot корзины/товаров, резерв, Purchase/Order/OrderItem и инструкция оплаты атомарно. Checkout key проверяется с сравнением запроса.
- Payments::ConfirmPurchasePayment: барьер на Purchase защищает от разных claim одной покупки, а не только duplicate одного callback.
- Settlement::SettleOrder: Order + все получатели/Wallet по стабильному порядку; отдельный ключ каждой роли; при любой ошибке rollback всех долей.
- Withdrawals::Request: wallet lock + проверка available + reserve entry + заявка + review/outbox. Complete: request + wallet + journal; внешнего перевода внутри транзакции нет.
- TelegramNotifications::Deliver: короткий claim lease, сеть без долгой блокировки БД, сохранение результата отдельной короткой транзакцией.

## Что не помещать в сервисы

Не передавать ActionController params целиком, request/session объекты, сырой клиентский actor, webhook secret в доменную модель. Не делать универсальный change_status без перечисления переходов. Не прятать выплаты, stock release и Bot API в callbacks save. Не создавать отдельный CRUD сервис для простого чтения, если достаточно scoped query.
